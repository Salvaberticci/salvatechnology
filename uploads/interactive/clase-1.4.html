CAPÍTULO 1 // EL ESCENARIO DE EJECUCIÓN

¿Dónde Despliega el Software?

Bienvenido de nuevo a SalvaTechnology Academy. En las sesiones anteriores dominamos el flujo entre las capas del software y cómo viaja un dato desde la memoria RAM del cliente hasta el disco duro de la base de datos. Hoy nos enfrentamos a una pregunta crucial que todo Arquitecto de Software debe resolver antes de escribir la primera línea de código o lanzar el primer prompt: ¿en qué entorno de hardware y sistema operativo va a vivir nuestro cliente?

El Error Infantil

Un error infantil en el desarrollo de aplicaciones es elegir una tecnología basándose únicamente en la moda o en la comodidad del desarrollador, en lugar de evaluar las necesidades reales del negocio y el contexto de ejecución del usuario. Hoy eliminamos ese error de tu repertorio.

🌐 EL ENTORNO WEB

Se ejecuta dentro del sandbox o caja de arena de un navegador (Google Chrome, Safari, Firefox). Es liviano, multiplataforma e instantáneo.

= NAVEGADOR · SANDBOX · INSTANTÁNEO

🔒 Toca para ver explicación

🖥️ EL ENTORNO DESKTOP

Se ejecuta directamente sobre el sistema operativo de una computadora (Windows, macOS, Linux). Tiene acceso sin restricciones al hardware del equipo y máxima potencia de procesamiento local.

= SISTEMA OPERATIVO · HARDWARE DIRECTO

🔒 Toca para ver explicación

📱 EL ENTORNO MOBILE

Se ejecuta en dispositivos de bolsillo (iOS, Android). Optimizado para pantallas táctiles, consumo de batería ultraeficiente y acceso a sensores físicos como cámara, GPS, giroscopio y biometría.

= BOLSILLO · TÁCTIL · SENSORES

🔒 Toca para ver explicación

Entender estos tres mundos te permitirá asesorar a tus clientes con precisión quirúrgica, eligiendo la arquitectura correcta que maximice el impacto y minimice los costos de desarrollo.

CAPÍTULO 2 // ARQUITECTURA WEB

Universalidad y Distribución Instantánea

Comencemos con la reina indiscutible del software moderno: la Arquitectura Web. ¿Por qué ha conquistado el mundo del software? Por un factor determinante: CERO FICCIÓN DE INSTALACIÓN.

La Magia: Cero Ficción de Instalación

El usuario no necesita descargar un archivo ejecutable, ni otorgar permisos de administrador, ni esperar actualizaciones en una tienda de aplicaciones. Simplemente escribe una URL en su navegador y el cliente descarga en milisegundos los archivos HTML, CSS y JavaScript necesarios para construir la interfaz en memoria RAM.

Ventajas Clave de la Web
🔄 Mantenimiento Centralizado

Corriges un error o lanzas una función en el servidor y el 100% de tus usuarios recibe la actualización al recargar la página.

🔒 Toca para ver explicación

💻 Independencia de Plataforma

Funciona exactamente igual en Windows, macOS, Chromebook o tablet si está bien construido.

🔒 Toca para ver explicación

📈 Bajo Costo de Adquisición

Arquitectura ideal para capturar clientes en la fase inicial de un negocio (funnel comercial).

🔒 Toca para ver explicación

Limitaciones Técnicas de la Web
🔒 Aislamiento de Seguridad (Browser Sandbox)

El navegador impide que el JavaScript acceda libremente al sistema de archivos local o a periféricos sin permiso explícito.

🔒 Toca para ver explicación

📡 Dependencia de Conectividad

Aunque existen las PWA, la mayoría de aplicaciones web pierden funcionalidad sin conexión a Internet.

🔒 Toca para ver explicación

🧠 Uso Efímero de Recursos

La memoria RAM del navegador está estrictamente limitada por la pestaña activa.

🔒 Toca para ver explicación

CAPÍTULO 3 // ARQUITECTURA DESKTOP

Potencia, Periféricos y Tolerancia a Fallos

Pasemos al gigante del rendimiento profesional. A menudo escuchamos la falacia de que "las aplicaciones de escritorio han muerto". Nada más falso: los softwares que mueven la economía global —suites de edición como Adobe Premiere, entornos de desarrollo como VS Code, sistemas de facturación de cajas registradoras y software médico— son aplicaciones Desktop.

Fortalezas Insuperables del Desktop
⚡ Acceso Directo al Hardware Nativo

Potencia bruta de procesadores multinúcleo, aceleración gráfica por GPU, RAM masiva y acceso directo al disco duro local sin la intermediación de un navegador.

🔒 Toca para ver explicación

🔌 Integración con Periféricos I/O

Reina para conectar impresoras térmicas de tickets, lectores de código de barras, básculas digitales, lectores de huella dactilar y puertos seriales/USB.

🔒 Toca para ver explicación

🔋 Operatividad Offline Ininterrumpida

Puede trabajar 100% autónoma durante días sin Internet, guardando transacciones en una BD local (como SQLite) y sincronizando cuando la red vuelve.

🔒 Toca para ver explicación

Desafíos del Desktop
📦 Distribución y Actualización Compleja

Actualizar una app Desktop requiere descargar un instalador o un parche en cada máquina cliente.

🔒 Toca para ver explicación

🪟 Dependencia del Sistema Operativo

Compilar y mantener versiones separadas para Windows (.exe/.msi), macOS (.dmg) y Linux (.deb/.AppImage) incrementa la carga de trabajo técnica.

🔒 Toca para ver explicación

CAPÍTULO 4 // ARQUITECTURA MOBILE

Movilidad, Sensores y el Ecosistema App Store

Entremos al dispositivo que acompaña al ser humano las 24 horas del día. El software móvil revolucionó la relación entre el usuario y la tecnología al trasladar el punto de contacto desde un escritorio estático hasta la palma de la mano.

Características Distintivas del Mobile
📡 Explotación de Sensores Físicos

GPS en tiempo real para mapas y transporte, cámara integrada para escaneo de documentos y QR, giroscopio y acelerómetro, aceleradores de redes neuronales (Neural Engine) y autenticación biométrica (FaceID/Huella).

🔒 Toca para ver explicación

🔔 Notificaciones Push

Capacidad de despertar la atención del usuario en cualquier momento con alertas relevantes directo en la pantalla de bloqueo.

🔒 Toca para ver explicación

🔋 Gestión Estricta de Batería y Memoria

iOS y Android son agresivos: si tu app consume demasiada RAM o recursos en segundo plano, el SO la destruirá sin contemplaciones para proteger la batería.

🔒 Toca para ver explicación

🏪 Ecosistemas de Distribución

App Store y Google Play: mayor confianza y seguridad para el usuario final, pero imponen comisiones comerciales del 15% al 30% y revisiones estrictas antes de cada actualización.

CAPÍTULO FINAL // MATRIZ DE SELECCIÓN

Síntesis & Actividad 1.4

¿Cómo decide un Arquitecto de Software qué plataforma utilizar? No se trata de intuición; se trata de evaluar variables técnicas y comerciales mediante una Matriz de Selección.

ELIGE WEB SI...

  • → Necesitas alcance inmediato y acceso sin instalación.
  • → Requieres ciclos rápidos de iteración.
  • → No usas periféricos complejos ni procesamiento gráfico ultra pesado.

ELIGE DESKTOP SI...

  • → Requieres uso intensivo de CPU/GPU.
  • → Necesitas periféricos físicos de tienda/fábrica.
  • → Toleras críticamente trabajar sin Internet.

ELIGE MOBILE SI...

  • → Tu valor depende del GPS o la ubicación.
  • → Necesitas cámara, notificaciones instantáneas o uso sobre la marcha.
  • → Requieres interacción táctil continua.
